# 正式部署文档

本文档面向「让微信公众号（日程-cq）真正能收发消息」的正式部署。仅本地测试请看下方 README / 测试方法.md，不需要本文。

## 一、核心前提

微信公众平台的「服务器配置 URL」**只接受 80(http) 或 443(https) 端口**，且必须公网可访问。因此必须二选一：

- 方案 A：一台有公网 IP 的云服务器（推荐，稳定）。
- 方案 B：本地机器 + 内网穿透（临时测试用，地址易变）。

## 二、方案 A：云服务器部署

### 2.1 安装环境

```bash
# 以 Ubuntu 为例
curl -fsSL https://deb.nodesource.com/setup_lts.x | sudo -E bash -
sudo apt-get install -y nodejs nginx
node -v && npm -v
```

### 2.2 部署服务

```bash
# 上传/克隆项目后
cd kindle-dashboard/server
npm install
```

编辑 `config.js`：
- `wechat.token` 改成一个自定义的复杂字符串（后台要填同一个）。
- `port` 保持 3000（由 nginx 反代对外）。

### 2.3 用进程守护常驻运行

用 pm2（断电/崩溃自动拉起、开机自启）：

```bash
sudo npm install -g pm2
pm2 start server.js --name schedule
pm2 save
pm2 startup   # 按提示执行输出的命令，实现开机自启
```

### 2.4 nginx 反代到 80/443

`/etc/nginx/sites-available/schedule`：

```nginx
server {
    listen 80;
    server_name your-domain.com;   # 或公网IP

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 10s;    # 微信要求5秒内响应，留足余量
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/schedule /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

### 2.5 配置 HTTPS（强烈建议）

```bash
sudo apt-get install -y certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com
```

certbot 会自动把 80 跳转 443 并续期证书。之后微信 URL 用 `https://your-domain.com/wechat`。

## 三、方案 B：本地 + 内网穿透（临时测试）

以 ngrok 为例（natapp / 花生壳 / frp 同理，关键是映射到公网 http/https）：

```bash
# 本地先启动服务（见 README）
ngrok http 3000
```

ngrok 会给出形如 `https://xxxx.ngrok-free.app` 的公网地址（已是 443），
微信 URL 填 `https://xxxx.ngrok-free.app/wechat`。

> 注意：免费 ngrok 地址每次重启会变，变了要回微信后台重新填 URL。正式用请走方案 A。

## 四、微信公众号后台配置

进入 公众号后台 → 设置与开发 → 基本配置 → 服务器配置：

| 项 | 值 |
|----|----|
| URL | `https://你的域名/wechat` |
| Token | 与 `config.js` 的 `wechat.token` **完全一致** |
| EncodingAESKey | 点「随机生成」 |
| 消息加解密方式 | **明文模式**（必须，否则后端无法解析） |

点「提交」——微信会向 URL 发 GET 做签名校验，服务已实现校验并返回 echostr，Token 一致且地址可达即通过。通过后点「启用」。

改了 `config.js` 的 Token 后需重启服务：`pm2 restart schedule`。

## 五、安全加固（上线前建议）

1. **必用 HTTPS**：明文模式下消息不加密，http 会暴露日程内容。
2. **给 POST /wechat 补签名校验**：当前仅 GET 校验了签名，POST 未校验，任何人知道地址都能伪造消息写库。建议在 POST 处理前复用 `checkSignature(req.query)` 校验 `signature/timestamp/nonce`，不通过直接返回空串。（需要我改代码可告知。）
3. **Token 用高强度随机串**，不要用默认的 `kindle_dashboard_token`。
4. **防火墙**：云服务器只开放 80/443，3000 只监听 127.0.0.1（nginx 本机反代，无需对外）。
5. **限制写入**：如担心被刷，可加简单频率限制或来源校验。

## 六、排查清单

| 现象 | 排查 |
|------|------|
| 后台提交「配置失败」 | 服务是否已启动、URL 是否公网可达、Token 是否两边一致、端口是否 80/443 |
| 发消息无回复 | 加解密方式是否为明文模式；`pm2 logs schedule` 看是否收到 POST |
| 收到但没建日程 | 看日志解析结果；标题/备注是否用两个空格或逗号分隔 |
| 回复超时 | nginx `proxy_read_timeout`、服务是否卡住（微信要求 5 秒内响应） |
